# Examples & playground

Every example on this page runs live, and the code under it is the exact file that runs.
Copy it into your app as it is. The examples share `data.ts`, a busy week of sample
events around today; it is in the second tab of each example.

<Callout type="info">
  The calendar fills its parent element. Give the parent a height, as every example
  does, and the hour views scroll inside it.
</Callout>

## Basics

### Calendar with navigation

`setCurrentDate` shows the navigation, `onViewChange` the view switcher, and `views`
picks the views it offers.

<Example name="BasicCalendar" />

### All seven views

Month, week, a week schedule, a day, a horizontal day timeline, and the week and day
grouped by hour. Overlapping items share the width like in Google Calendar, multi-day
items sit in their own lanes, and items crossing midnight are split across their days.

<Example name="AllViews" height={620} />

### Working hours and a 24-hour clock

`startHour` and `endHour` limit the hours, `weekStartsOn` picks the first day of the
week, and `timeDateFormat` sets any [date-fns format](https://date-fns.org/docs/format).

<Example name="WorkingHours" height={560} />

### A busy month

Days with more items than `dayMaxItems` end with "+N more", which opens the list of
the day. `'auto'` fits as many items as the cell height allows.

<Example name="BusyMonth" height={650} />

## Interaction

### Create and edit events

Click an empty slot to add an event and an event to edit it. `onCellClick` receives a
[`DateInfo`](/types#supporting-types) with the start of the clicked cell, and `Calendar<Event>`
types the items in every callback.

<Example name="CreateAndEdit" height={610} />

### Open a day from the month

Day numbers and weekday names report their day; switch the view to show it.

<Example name="DrillDown" />

### Every callback

Each callback prints what it receives. Click items, empty slots, day names, day
numbers, hour labels, "+N more" and the red dot.

<Example name="Callbacks" height={680} />

### Load events for the visible range

`getViewRange` returns the days the calendar shows, so you fetch only those, again

`renderNavigation` replaces the toolbar. It gets the title and the actions, so the

### Next.js App Router

Fetch on the server and render the calendar in a Client Component. It shows "today"
and places items in the visitor's time zone, so render it in the browser only.

```tsx filename="app/schedule/page.tsx"
import Schedule from './Schedule';

export default async function SchedulePage() {
  const events = await getEvents(); // your data source
  return <Schedule events={events} />;
}
```

```tsx filename="app/schedule/Schedule.tsx"
'use client';

import dynamic from 'next/dynamic';
import { useState } from 'react';
import type { CalendarItem, CalendarView } from 'react-lightweight-calendar';

const Calendar = dynamic(() => import('react-lightweight-calendar'), { ssr: false });

export default function Schedule({ events }: { events: CalendarItem[] }) {
  const [view, setView] = useState<CalendarView>('WEEK_TIME');
  const [date, setDate] = useState<string | Date>(new Date());

  return (
    <div style={{ height: 640 }}>
      <Calendar
        data={events}
        activeTimeDateField="start-end"
        currentView={view}
        onViewChange={setView}
        currentDate={date}
        setCurrentDate={setDate}
      />
    </div>
  );
}
```
